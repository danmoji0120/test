# V4.2 성능 측정 방법

환경: Linux 클라우드 컨테이너, Node24.19.0, Chromium154.0.8037.57, cgroup CPU quota2. 하드웨어 GPU 없는 headless/software 환경입니다. Windows 데스크톱 GPU나 서로 다른 장치 LAN/WAN 결과로 해석하지 않습니다.

## 비교 조건

- V4.1 `51f7432`와 V4.2를 같은 환경에서 순차 실행합니다. 기존 `render-benchmark.html`의 동일 Seed42/6400×4200/아군4·적20/Fog·경보4/동일 혼합 편성·발사 이펙트·투사체를 사용합니다. 시각 부하를 고정하기 위해 장애물을 제거한 통제 fixture입니다. 실제 임무 성공이나 난이도 증거가 아닙니다.
- 1920×1080·1280×720 각각 브라우저1/2/4개,15초 관측. 페이지별 프레임 평균/p95·draw 비용·JS heap과 Chromium 전체 RSS를 기록합니다. 개별 페이지 heap을 전체 사용량처럼 합산하지 않습니다.
- 서버 비교는 같은 구형64명 지형 fixture를 양쪽에서 실행합니다. 이 fixture는 모든 적이 근거리에서 교전하는 조건이 아닙니다. 이를 정상 작전30Hz 달성 근거로 사용하지 않습니다.
- 추가 V4.2 서버 fixture는 실제 standard/expanded 지형을 보존하고 근처 혼합 병력20/30명과 극단64명을 나눠30초 시뮬레이션합니다. 표적4명의 높은 HP·작업 설비의 높은 내구와 출동 제한은 측정 동안 부하를 유지하기 위한 명시적 통제이며 실제 게임에 적용되지 않습니다. 총알·장갑·부위·관측·시야·경로·스냅샷 판정은 실제 함수를 사용합니다.
- 실제 production 브라우저의 서버 trace는 별도로 틱 처리/타이머 간격/패킷/메모리를 기록합니다. 틱 처리 p95만으로33.3ms 타이머가 항상 지켜졌다고 주장하지 않습니다.

## 대형 지형과 메모리

`v42-render-fixture.html`은 네 크기의 실제 생성 지형/Fog/PNG를 렌더링한 뒤 통제된 카메라 순회로 LRU를 검사합니다. 카메라/플레이어 위치를 옮기는 명시적 fixture이므로 게임플레이 이동 증거로 사용하지 않습니다. production DOM 입력 작전은 별도 디렉터리에 있습니다.

1024×1024 RGBA 지형 표면16개는 최대64MiB 논리 캐시입니다. 대체 청크를 할당하기 전에 기존 표면 width/height를0으로 회수합니다. 이는 브라우저 전체 GPU·PNG·임시 래스터·JS heap 사용량 상한이 아닙니다. Fog는 저해상도 전체 월드 표면을 유지하며 expanded2560×1680 약16.4MiB, 미니맵256×168입니다. terrainRenderer는 전체12800×8400 Canvas를 만들지 않습니다.

원점이 같은 표면의 로드 순서/발견 상태 변경 후 재생성은 byte-exact로 검사합니다. 별도로2048넓은 표면과1024청크 두 개의2097152픽셀을 비교합니다. 독립 클리핑 시 Skia의 안티앨리어싱 양자화는 채널4/255까지 허용하고 원본 차이·최대값을 기록합니다. 재생성의 차이는 허용하지 않습니다. 지형/도로 경계의 큰 차이와 LRU 위반은 실패합니다. functional 사전 검사는 최대차이1–3/255·재생성0을 확인했으며 최종 격리 측정은 아래 결과 파일로 구분합니다.

## 재현

```sh
npx tsx scripts/v42-performance-suite.ts
QA_SCRIPTS=scripts/v42-render-qa.ts QA_OUTPUT=docs/v4.2/performance/world-render npx tsx scripts/dev-qa-session.ts
npx tsx scripts/v42-server-performance.ts
```

첫 명령은 Git archive/tar로 V4.1을 별도 `.qa-private-v41-reference`에 보존하고 node_modules만 공유합니다. `QA_V41_REFERENCE_ROOT`로 이미 추출된 경로를 지정할 수 있습니다. 기본 Chromium은 `/usr/bin/chromium`이며 `CHROMIUM_PATH`를 사용하는 일반 브라우저 QA와 동일한 설치가 필요합니다. POSIX 예시 환경변수는 PowerShell에서 `$env:이름="값"`으로 설정하세요.

실측 수치와 원본 파일 연결은 아래에 기록했습니다. 사람 플레이의 재미·적정 임무 길이·60FPS 보장은 자동 생성/입력 검사에서 추론하지 않습니다.

## 실제 생성 지형 네 크기

이 표는 AI를 틱하지 않는 정지 지형/Fog/PNG 렌더 fixture입니다.20적 동시 전투와 다른 부하입니다. 동일1920×1080,12초 관측 후 카메라 순회했습니다.

초기 지형 표면은 네 크기 모두24MiB이고 순회 후 최대64MiB입니다. 전체 맵 면적이14배가 되어도 초기 표면 수나 이 정지 장면의 프레임 비용은 같은 비율로 증가하지 않았습니다. 반대로 생성/경로 검사 비용과 저해상도 Fog 비용은 커집니다. 순회에는 새 청크 생성 지연이 있으므로 정지60FPS를 이동 중 항상60FPS라는 뜻으로 쓰지 않습니다.

구형 동일64개체 지형 서버 fixture의 틱p95는 V4.1 11.90ms→V4.2 4.08ms, 틱+스냅샷p95는12.37→4.49ms였습니다. 이 경우 많은 병력이 먼 전략 이동 상태이므로20–30근거리 교전의 근거로 대신하지 않습니다. 원본 `performance/v41-server/server-terrain-stress.json`, `performance/v42-server/server-terrain-stress.json`을 보존합니다.

## 근거리20/30명과64명 과부하

최종 `performance/operational-server/server.json`은 모든 행이 실제30초를 틱했음을 검사합니다. 표적과 필수 작업 설비의 HP를 높여 측정 중 작전 실패로 시뮬레이션이 멈추지 않게 한 통제 fixture입니다. 초기 버전의 중도 종료 가능성을 발견한 결과는 tuning/unprotected-server-fixture에 보존하고 최종 수치에 사용하지 않았습니다. 지형·엄폐는 그대로이므로 가까운 모든 적이 항상 사격하는 조건은 아닙니다. 출동을 중지해 초기 개체 수를 고정했습니다.

| standard |   20 |     1.03/4.99 |               5.28 |     17.4 |     173.6 |       607.4 |    27.6 |
| standard |   30 |     1.13/5.61 |               6.16 |      9.2 |     175.1 |       702.3 |    46.3 |

이 격리 CPU fixture의20–30병력 처리는33.3ms 예산 안에 있었고64극단 조건도 별도로 기록했습니다. 실제4브라우저를 같은2CPU에서 함께 실행할 때의 타이머 지연까지 보장하지 않습니다. heap은 샘플 당시 GC 전 수치이며 판누수에는 별도의 반복GC 실험을 사용합니다. WS는 JSON 애플리케이션 페이로드로 TCP/HTTP/PNG 전송량을 포함하지 않습니다. 조밀한4인 관심영역은 후속 페이로드가 약0.6–1MiB/s/클라이언트에 달해 네트워크 상태 델타 최적화가 남아 있습니다. 정적 맵과 탐색 전체를 매 스냅샷 반복하지는 않습니다.
