# V4.2 실제 미션 규칙

정의는 `src/shared/missions.ts`, 그래프 판정은 `game/mission-graph.ts`, 서버 작업은 `game/operational-objectives.ts`에 있습니다. 시설과 목표 ID는 독립적입니다. 목표는 이미 존재하는 시설에 연결되며 선행 목표 완료 시 새로운 시설이 생성되지 않습니다.

표의 시간은 서버 작업량/제한시간이며 인간 플레이 타임 측정 결과가 아닙니다. 작업·발사 단계의 자동 진행 중에는 E를 계속 누를 필요가 없습니다. 방어는 무한 웨이브가 아니며 주변 주둔군은 계속 활동합니다. 적은 실제 사선·조준 획득·회전을 거쳐 시설에 사격합니다. 적이 없는 경우 시설에 가짜 피해를 주지 않습니다.

## 그래프와 실패

`available / active / locked / complete / failed`를 사용합니다. 기존 `complete` 상태 이름을 보존합니다. ALL/ANY, 별도 최종 완료 ID 집합과 명시적인 개수 조건을 지원합니다. 순환·유실 참조·중복 ID·빈 ANY·불가능한 개수·선택 목표의 필수 봉쇄를 검출합니다. 원자로처럼 명시적인 강제 돌파 경로가 있으면 선행 설비 파괴만으로 실패하지 않습니다. 최종 조건이 더 이상 충족될 수 없을 때 실패합니다. 완료·효과 적용은 서버에서 한 번만 처리합니다.

잠긴 목표는 선행 조건을 표시하지만 미발견 시설의 정확한 좌표·역할·상태는 공개하지 않습니다. 필수 선행 목표는 대략750단위의 추정 지역으로 안내하며 실제 발견 후 정확하게 추적합니다. 자동 안내는 잠긴 최종 목표보다 진행 가능한 선행 목표를 우선합니다. Tab 수동 추적을 지원합니다.

## 데이터 케이스

케이스는 출격 시 실제 회수 설비 옆에 존재합니다. 인증 전에는 회수할 수 없습니다. 운반 중 위치는 서버의 운반자 위치를 따르고, X/쓰러짐/연결 종료/퇴장 시 그 위치에 떨어집니다.0.3초 후 회수 가능하며 다른 플레이어가 이어받을 수 있습니다. 운반자 주무장 발사는 서버에서도 거부합니다. 인증/전송 완료를 클라이언트가 위조할 수 없습니다. 전송은 케이스를 실제로 가져온 플레이어가 시설에서 수행해야 합니다.

## 선택 목표와 POI

- 통신시설: 2400범위의 출발지 준비시간×1.8, 인근 적 무전 약화. 다른 지역은 유지합니다.
- 병영·감시초소: 연결된 실제 출동지를 비활성화합니다. 이미 행군 중인 병력은 사라지지 않습니다.
- 레이더·정보 저장소: 1800범위 정적 시설/POI를 발견합니다. 적 위치·현재 시야를 제공하지 않습니다.
- 보급 시설·탄약 창고·버려진 수송차: 팀 공용 유한한 보급 상자 한 개를 추가합니다. V4.1 소유 장비별 보급 상한을 유지합니다.
- 포병 지휘시설: 연결된 실제 포병의 무장 기능을 파손하고 후속 포병 투입을 차단합니다. 이미 발사된 포탄은 유지됩니다.

## 결과와 기존 시스템

필수 완료 후에도 적 활동은 계속됩니다. 기존 E 요청→24초 실제 수송 도착→연결된 생존자140거리/3초 집결을 유지합니다. 결과의 `primaryAchieved`와 `extracted`는 별개입니다. 목표 완료 후 전멸하면 성공 귀환으로 표시하지 않습니다. 보상·중복 정산 방지·프로필 형식2는 기존 체계를 유지하고 목표 보상은 실제 완료 노드에만 더합니다.

구형 서버 테스트/클라이언트가 operation 설정을 생략한 경우 V4.1 BLACKOUT을 호환 경로로 유지합니다. 현재 게임 UI는 여섯 V4.2 작전을 선택해 전송합니다. 기존 전투 데이터/저장 스키마를 새 미션 때문에 초기화하지 않습니다.
