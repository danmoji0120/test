# PROJECT DOLL SQUAD V0.1 — QA

검증일: **2026-10-14 KST**. 구현된 동작, 자동화된 플레이, 시각 검토, 사람의 체감 검증을 구분합니다. 스크린샷은 실제 실행 중 캡처이며 합성 콘셉트 이미지가 아닙니다. `render-benchmark.png`만 명시적인 합성 부하 테스트 장면입니다.

## 환경

- Linux x86_64, Node 24.19.0, Chromium headless (버전은 측정 JSON 참조).
- 가상화된 AMD EPYC 9V74, 노출된 vCPU 3개, RAM 약 9.7 GiB.
- Canvas 2D. 별도 GPU 가속을 보장하지 않는 클라우드 환경.
- 실제 Windows PC, 다른 물리 PC의 LAN, 서로 다른 인터넷 회선은 검증하지 않았습니다.
- HTTP/WebSocket 로컬호스트 검증. 프로덕션 `npm start` 서버에서도 전체 작전을 검증합니다.

## 자동 테스트

**30개 테스트 통과.** 최종 실행 로그는 `docs/test-results.txt`. 검사 항목:

- Seed 재현과 차이. 100 Seed × 목표·보급·탈출 경로 도달성.
- 벽 충돌, 슬라이딩, 시야 차단, 레이의 가장 가까운 교차점.
- 세 무기의 탄약 소모·산탄 수·피해, 엄폐 차단, 아군 무피해.
- 탄약 보존 재장전, 장전 중 사격 금지, 질주 중 사격 금지, 대각선 정규화.
- 소생 속도, 거리/벽 차단, 전원 쓰러짐, 종료 후 중복 판정 방지.
- AI 벽 관통 방지, 불투명 벽 뒤의 플레이어 미탐지, 사망 적 제거.
- 동시 상호작용 시간 고정, 일회 보급, 동료 전원 탈출 조건.
- 입력만으로 4인 전체 임무 성공. 체력/탄약/위치를 테스트가 강제로 수정하지 않음.
- 실제 WebSocket 5번째 참가 거부, 방장/준비 권한, 입력 범위 제한, 동시 사격, 재접속 신원 유지, 모든 방 정리.
- 연결이 모두 끊긴 로비에 새 대원이 들어오면 방장을 승계하고 연결된 대원으로 출격.
- heartbeat는 중복 방 스냅샷을 유발하지 않으며 정해진 상태 전송 주기를 유지.
- 개발 서버의 저장 디렉터리 직접 요청 및 `/@fs/` 우회 요청 403 차단, 프로필 토큰 미노출.
- 잠긴 장비/잘못된 캐릭터 거부, 구매와 재접속 후 해금 유지.
- 서버 저장 재시작 복원, 동일 실행 ID 중복 보상 방지, 손상된 기본 파일의 백업 복구.

## 입력 기반 전체 시뮬레이션

`npm run qa:sim`, 원시 결과: `docs/simulation-qa.json`.

1·2·4인 × Seed 7·42·103의 **9개 작전**. 8회 성공, 1회 전멸(1인 / Seed 42). 실패도 정상 상태 머신 결과이며 테스트 오류로 숨기지 않았습니다. 자동 파일럿이 이동·조준·사격·재장전·보급·소생·상호작용 입력을 생성하고 같은 게임 시뮬레이션을 실행합니다. 렌더링과 실제 네트워크 검증을 대체하지 않습니다.

성공 소요: 339.1–353.5초. 자동 파일럿은 정확한 맵/적 위치와 즉각적인 조준을 사용하므로 사람이 플레이하는 시간이나 난도를 대표하지 않습니다. 기획의 **8–12분은 사람 분대 대상 목표**이며 아직 사람 테스트로 달성했다고 주장하지 않습니다. 현재 최단 자동 진행은 약 6분입니다.

## 실제 브라우저 플레이

`npm run qa`, 증거 요약: `docs/browser-qa.json`; 동일 방 재접속·재출격 원시 기록: `docs/resume-qa.json`.

**4인 작전 성공: 게임 내 07:31, 86처치, 기밀 회수, S등급, 각 580 CR.** 네 프로필 모두 880 CR / 1회 출격 / 1회 승리를 저장했고, 같은 방에서 새로운 실행 ID로 재출격했습니다.

네 개의 격리된 Chromium 컨텍스트에서 실제 UI 클릭, DOM 키보드·마우스 입력, 실제 WebSocket 서버를 사용합니다. `window.dollQA`는 관찰용 상태 getter이며 게임 상태를 변경하는 명령을 제공하지 않습니다. 기본 성공 경로는 오퍼레이터 2종과 AR-01 4정으로 로비 → 준비 → 침투 → 설치 → 방어 → 탈출 → 결과 → 다음 출격을 검사합니다.

- 중간 브라우저 새로고침 후 동일 오퍼레이터·동일 작전 복귀.
- 참가자 전체의 동일 실행 ID와 동일 결과.
- 결과 화면 표시와 보상 이후 다음 출격의 새로운 실행 ID.
- 1920×1080 / 1280×720 실제 렌더링 캡처.
- `npm run qa:smoke`: 1인 30.2초 / 9처치, 2인 30.0초 / 각각 7·4처치. 동일 작전 ID와 탄약 동기화, 브라우저 오류 0건. `docs/smoke-qa.json` 참조.

혼합 무장(AR·SMG·SG)의 선행 실행은 409.4초에 탈출 도중 전멸했고 실패 보상 340 CR와 부상 표정을 확인했습니다(`docs/mixed-loadout-qa.json`, `result-failed.png`). 당시 종료 시점의 추가 증원 버그와 QA 드라이버의 결과 화면 전환 경합을 수정했습니다. 이를 성공 검증으로 계산하지 않습니다.

성공 결과와 네 클라이언트의 결과 일치 검사 이후, QA 스크립트가 로비 새로고침으로 이전된 방장 권한을 반영하지 못해 이전 방장의 출격 버튼에서 대기했습니다. 게임은 올바르게 버튼을 비활성화했습니다. 같은 방에 네 테스트 프로필로 유예 시간 안에 복귀하여 현재 방장으로 재출격을 검증했습니다. 스크립트도 현재 방장 선택 및 결과 우선 저장 방식으로 수정했습니다. 게임 내 상태나 타이머를 강제 변경하지 않았습니다.

첫 개발 서버 실행은 QA 파일 추가에 따른 Vite 자동 새로고침으로 중단되어 완료로 처리하지 않았습니다. 이후 프로덕션 서버에서 검증을 다시 수행했습니다. 수정 이력은 `docs/CHANGELOG.md`에 남겼습니다.

## 반복 안정성

`npm run qa:stability`, 원시 결과: `docs/stability-qa.json`.

- 4인 자동 작전 **40회** 연속 생성·진행·종료. 36회 성공, 4회 전멸. 정상 종료와 상태 정리를 모두 포함합니다.
- 이벤트 버퍼 상한 160, 동시 적 상한 22 확인.
- 5회마다 명시적 GC 후 힙: 7.51 → 7.52 → 7.73 → 7.74 → 7.78 → 7.81 → 7.88 → 7.91 MiB.
- 샘플 28,220개의 서버 단일 틱: 중앙값 0.060ms, p95 0.122ms, p99 0.157ms.
- 작은 힙 변화는 관찰했지만 이 범위에서 지속적인 큰 누수는 보이지 않았습니다. 이는 수일간 서버 운영이나 모든 입력에 대한 무누수 증명은 아닙니다.
- 네트워크 테스트는 방 이탈 후 방 수 0을 확인합니다. 소켓 종료 시 입력을 제거하고 만료된 대원과 예약 정보도 정리합니다.
- 클라이언트 이벤트 ID로 중복 효과를 막고, 입자는 최대 400, 효과 수명은 자동 정리, 위치 캐시는 사라진 엔티티를 제거합니다. 화면 전환 시 기존 requestAnimationFrame을 취소합니다.

## 성능

실제 네 브라우저의 전체 작전 성공은 확인했지만, 후속 QA 스크립트의 방장 선택 오류로 그 실행의 프레임 샘플 버퍼는 파일에 남기지 못했습니다. 해당 수치를 추정하거나 재구성하지 않았습니다. 4개 브라우저를 동일한 3-vCPU 머신에서 실행하는 경우와 일반 PC 한 대에서 한 브라우저를 실행하는 경우도 구분해야 합니다.

별도 `npm run qa:render`는 1920×1080, 4 캐릭터, 20 적, 다수 사격·피격 효과의 **합성 렌더링 부하**를 측정합니다. Chromium 154.0.8037.57에서 600프레임의 중앙값 **16.70ms**, p95 **16.90ms**, 평균 **16.67ms (약 60 FPS)**였습니다. 원시 결과는 `docs/render-qa.json`. 실제 작전 성공 증거로 이 합성 화면을 사용하지 않습니다. 60 FPS는 목표이며 모든 하드웨어에 대한 보장이 아닙니다.

## 남아 있는 한계

1. **사람 분대의 재미/난도/8–12분 템포 검증 전.** 입력 파일럿과 화면 검토가 사람 플레이를 대체하지 않습니다.
2. **인터넷 배포 및 WAN 지연 검증 전.** 로컬 예측/롤백이 없어 높은 지연에서는 이동·사격 반응이 늦어집니다.
3. **실제 Windows·일반 데스크톱 60FPS 검증 전.** 클라우드 Chromium 측정값과 구분해야 합니다.
4. AI는 간단한 시야·순찰·거리 유지·엄폐 가장자리 탐색입니다. 적끼리의 충돌/분대 전술은 없고 좁은 통로에서 겹칠 수 있습니다.
5. 머리는 얼굴 가독성을 위해 기울어진 정면을 유지합니다. 정밀한 방향별 머리·몸 회전, 자연스러운 머리카락 물리, 프레임별 연출은 없습니다.
6. 사운드는 절차적이며 무기별 차이는 구현했지만 스튜디오 수준의 잔향/공간음향은 없습니다. 자동화에서는 오디오 경로의 오류 유무를 확인했으며 사람의 청음 품질평가는 하지 않았습니다.
7. 방·작전은 서버 메모리 상태입니다. 서버 재시작은 작전을 끝내며 진행도만 복원합니다. JSON 저장은 단일 서버용입니다.
8. 영구 계정·프로필 이전 UI·채팅/음성채팅은 없습니다. 같은 브라우저 프로필의 탭은 동일 대원이며 별도 플레이어 테스트에는 격리된 컨텍스트가 필요합니다.
9. 방어는 발전기 HP가 아닌 분대 생존 방식입니다. 적이 목표물을 공격하는 별도 방어 AI, 무기별 전용 총구 모양/탄착 팔레트, 임무 시작 전용 시네마틱 화면은 없습니다.
10. 단일 맵 템플릿 안에서 시작/탈출·소품·적·목표 배치가 변합니다. 새로운 맵 구조나 개방형 세계는 구현하지 않았습니다.
