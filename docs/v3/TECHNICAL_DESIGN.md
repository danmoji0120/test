# V3 OPERATIONAL WARZONE — implementation contract

Baseline: V2 `014ce837f601`, clean main. Retain authoritative combat, three weapons/recoil, raster art, camera/audio, rooms/reconnect/settlement and input-based QA. V2 evidence remains under docs/v2.

1. Visibility: shared 360° finite-range ray polygons, solid walls/containers/closed doors occlude, low crates do not. Server refreshes at 5Hz; conservative explored grid + exact current polygons. All clients share the same visibility. Snapshots strip hidden enemies, private AI/path/intel, hidden enemy attack events and hidden dynamic facility states. Audio-only cues are quantized sectors, never exact origins or target coordinates. Client fog uses cached masks, not full-map per-frame ray casts.
2. Region: seeded spaced facility footprints and a connected road graph plus extra loops, outdoor lanes/rock belts, varied internal prefabs and two entrances. Start at V2 area 5000×3300. Generator objectives in separate facilities; independent comms/intel/outposts; three extraction candidates; outpost/barracks/border reinforcement sources have actual doors, spawn corridors and navigation routes. Validate 100 seeds and compare three executed seeds.
3. Perception: explicit patrol/suspicious/investigate/engage/request-support/pursue/regroup/return states. Squads share timestamped observed or uncertain heard positions, not live hidden player coordinates. Alert 0–4 has decay and permanent objective-destruction floor. Rifle bursts use short reactions, heavy-only firing line. Tactical goals vary by squad role.
4. Reinforcements: request→select reachable source→queue/preparation/warning→physical march→arrival/deploy; queued cap, finite local reserves, renewable border source. Reserve troops already exist at operation start, initially inside occluded source alcoves, so no observed-floor spawning. Every dispatched soldier has source/request IDs and sampled trajectory. Destroyed/blocked sources cancel or reroute pending requests; active travelers continue. No kills-trigger-spawn replacement. Director evaluates current engagement, team size, alert and elapsed support interval, caps 30 active actors.
5. Objectives: remove checkpoint/encounters entirely. Two independently damageable generators, destroyable comms/outposts/barracks, optional intel E. No kill gate. Both generators enable E request at any extraction candidate; visible transport approaches then lands before boarding timer. Enemy simulation continues throughout objective completion and extraction. Objective-heavy rewards, kill bonus capped low. One existing BLACKOUT contract, optional full-recon contract changes bonus focus without adding new content.
6. Difficulty: numeric1–10 parameters for garrison/reserve/patrol cadence/reaction/radio/prep/dispatch/pressure; HP unchanged. Solo allowed at every level. Measure before optimizing tick/snapshot rates.

Modules: visibility/perception/alert/squads/reinforcements/director/objectives/extraction; simulation retains movement/combat orchestration. Static generation is separate from geometry/navigation. Versioned snapshots retain shared types but have sanitized collections. No QA mutation endpoints. Each verified phase builds/tests and commits; final tests include public-state-only pilots, real WebSocket filtering, browser operations and continuous reinforcement provenance. Human fun/timing remains unverified unless humans actually participate.
