# V3 QA — 실제 결과와 한계

검증일2026-10-15 UTC. 기준 V2 `014ce837f601`, 단계별 커밋으로 V3 구현. 실행한 원본 로그/JSON/캡처는 `docs/v3/`에 있으며 V2 기록은 `docs/v2/`에 보존했습니다.

## 환경과 검증 수준

Linux x86_64, Node24.19.0, npm11.9.0, Chromium154.0.8037.57, Playwright. AMD EPYC9V74 논리CPU3개이지만 cgroup CPU 할당은 **2코어**, 메모리 한도8GiB입니다. 실제 브라우저는 로컬호스트의 서로 격리된 컨텍스트와 정상 키보드/마우스 DOM 입력으로 제어했습니다. 서버 상태를 바꾸는 QA 전용 API, 순간이동, 무적, 강제 타이머 종료는 사용하지 않았습니다. 단위 테스트의 격리 fixture와 실제 플레이 증거는 구분합니다.

사람이 직접 플레이하거나 청음한 기록은 없습니다. 화면을 직접 검토했지만 자동 조종 성공을 재미·긴장감·반복 플레이 의향 검증으로 간주하지 않습니다. Windows 실기, 다른 PC의 LAN, 실제 원격 인터넷/WAN은 미검증이며 공개 서버 배포도 수행하지 않았습니다.

## 실제 출입구 증원 검증

[실제 출입구 캡처](docs/v3/final-source/emergence-e18-12.1.png), [실제 영상](docs/v3/final-source/source-emergence.webm), [서버 궤적+브라우저 대조](docs/v3/final-source/continuity.json).

두 브라우저가 Seed7의 병영 출입구로 이동하고 최초 관측2.1초 동안 멈춰 경비의 무전을 기다린 뒤 정상 사격했습니다. 적 위치/HP/경보를 강제로 바꾸지 않았습니다. 실제 발진 문이 열리고 시작부터 안에 있던 e18/e19가 걸어 나왔습니다. 브라우저가 두 병사를 관찰했고 한 병사의100단위 이상 이동도 관측했습니다. 둘은 문 앞 교전에서 사망했으므로 요청이 `deployed`가 아니라 병력 손실 취소로 끝난 것은 정상입니다.

감사한4명 전원이 유효한 출발점·경로·연속 좌표를 가졌습니다. 외곽2명은 실제 지도 밖에서 출발해42개 이동 표본을 남겼고 브라우저에서는 관찰되지 않았습니다. 외곽 출발과 게이트 통과는 별도 단위 테스트 및 위 입력 회귀에서도 검사했습니다. 시야 밖이었다는 사실만으로 정상 판정하지 않았습니다.

영상은 실제85초 관측 기록의 처음24초를 무재구성 추출한 파일입니다. Playwright용 FFmpeg 다운로드가 환경 정책의403으로 막혀 설치된 시스템 FFmpeg7.1.5를 사용했습니다. 원본 영상은 로컬 비공개 QA 폴더에 보존했습니다. 게임 실행에는 FFmpeg가 필요하지 않습니다.

## 성능과 안정성

합성 렌더 부하:1920×1080, 아군4·적20이 모두 표시되는 개방 fixture, Fog/보간/사격/파편,600프레임. **중앙값16.6ms, p95 19.4ms, 평균16.67ms**. [결과](docs/v3/final-performance/render-qa.json). 이것은 성능 fixture이며 실제 플레이 화면으로 제출하지 않습니다. RAF를 멈춘 상태의10,000개 이벤트 시험에서도 기존 파티클 상한400, 궤적 상한120이 유지됐습니다.

| 실전 렌더 조건         | 프레임 중앙값 | p95    |
| ---------------------- | ------------- | ------ |
| 실제 브라우저 1개 동시 | 16.2ms        | 28.3ms |
| 실제 브라우저 2개 동시 | 17.3ms        | 40.3ms |
| 실제 브라우저 4개 동시 | 50.8ms        | 92.0ms |

브라우저4개를 같은2코어 할당에서 동시에 렌더하면60FPS에 도달하지 못합니다. 단일 화면 결과를4개 동시 실행 성능으로 바꾸어 보고하지 않습니다. 실제 작전은 서버 고정 스텝 시간이므로 과부하에서는 벽시계보다 작전 시계가 느려질 수 있습니다. 위 표의 작전시간은 서버 시계입니다.

40회 반복 공개 상태 작전: **40성공/0실패**, 최대 적21명/이벤트160개. GC 후 heap 9.27–9.48MiB, 일방적 증가를 관찰하지 않았습니다. 서버 시뮬레이션 틱 중앙값0.107ms/p95 2.632ms/p99 5.389ms. [반복 결과](docs/v3/final/stability-qa.json). 이는 틱 함수 비용이며 HTTP/소켓 직렬화/실제 WAN 지연을 포함한 전체 서비스 지연은 아닙니다. 완전한 장기 운영/브라우저 힙 프로파일링은 미실시입니다.

실제 스냅샷 인코더를15Hz로 샘플링한 페이로드 수치는 입력 회귀 JSON의 `snapshotBytes`에 있습니다. 정적 맵은 초기1회, 동적 상태는15Hz, 시야는 revision 변화 때만 포함됩니다. 시야 갱신 패킷은 일반 동적 패킷보다 크며 압축/격자 증분 전송은 구현하지 않았습니다.

실제 AudioEngine의 세 총성을 Chromium OfflineAudioContext로 WAV 출력했고 각기 다른 attack/tail과 clipping0을 확인했습니다. [음향 수치/파일](docs/v3/final-performance/audio-qa.json). 이것은 청음 평가가 아닙니다.

## 시각 검토·실패 이력·남은 한계

[전후 실제 화면](docs/v3/COMPARISON.md). PNG 실루엣과 색 구분, 벽 모서리 사각지대, 탐색 기억, 미니맵 은폐, 두 해상도의 HUD, 출입구 병력, 착륙체·결과·재출격을 검토했습니다. 처음 잘려 보이던 탈출 수송기는 착륙 지점을 화면 안쪽으로 옮겼습니다. 점검 중 발견한 실내 코너 항법 여유, 최초 지원 대기/경보 승격, QA 조종기의 탈출 집결 문제를 수정했습니다.

초기 전멸(`tuning/phase5-combat`), 항법 중단 로그, 탑승 시간 초과(`phase5`), 지원 호출이 발생하지 않은 관찰(`tuning/source-*`)을 삭제해 성공처럼 포장하지 않았습니다. 실패 영상의 전체 원본은 로컬 QA 폴더, 로그·JSON·스틸은 저장소에 남겼습니다. 중간 자료는 최종 성공을 대신하지 않습니다.

알려진 한계:

- 사람의 재미·긴장감·반복 의향과8–14분/선택 목표14–20분은 미검증이며 자동 조종은 훨씬 빨리 끝냅니다.
- 1–10의 편성/규칙은 검사했지만 모든 단계의 실제 사람 밸런스를 검증하지 않았습니다. 일부 배치는 투입 직후 빠른 접촉이 가능합니다.
- 정적 지형은 클라이언트에 포함됩니다. 동적 적/공격은 필터하지만 정적 맵까지 비밀로 보장하는 안티치트는 아닙니다.
- 시설12개의 기준 위치 순열·오프셋·크기·도로 연결을 바꾸는 모듈 생성입니다. 완전한 자유형 자연 지형은 아니며 같은 실내 모듈이 반복됩니다.
- 아군/적 상호간 정교한 회피나 몸체 충돌이 없어 밀집 시 포즈/이름이 겹칠 수 있습니다. 수송기는 간단한 코드 실루엣과 접근/착륙 상태이며 차량 물리는 없습니다.
- PNG는 네 방향 정적 포즈이며 독립 팔/총기 애니메이션·무기별 몸체 실루엣·표정3종을 추가하지 않았습니다.
- WAN 이동 예측/롤백/지연 보정, 공용 서버 배포/실제 외부 회선, Windows 실기는 미검증입니다. 서버 재시작 시 진행 중 작전은 복구되지 않습니다.
- 외부 증원은 재생 가능하지만 총 병력30/요청 상한 때문에 출동이 지연될 수 있습니다. 원거리 부대의 별도 전략 추상화는 필요성이 측정되지 않아 도입하지 않았습니다.
